the looper then marks it `promoted` or `declined` here with the date.

- **ROADMAP.md: #3 is done; #5 may already be** (2026-10-29, #3): the module is `github.com/tacplus-dev/blobstore` and no SeaBeam reference is left outside PROVENANCE.md and the planning records (the gates now check it). ROADMAP.md's "Later" line for #3 can go. #5 is done too (Dockerfile base `alpine:3.24` as a build argument, gates and image build verified 2026-10-29), so a ROADMAP.md line for it can go as well. Needs an agent at Jody's request.
- **Old xz and klauspost/compress in the module graph** (2026-10-29, #4): `go list -m all` still lists github.com/ulikunitz/xz v0.5.6 and github.com/klauspost/compress v1.4.1 (GHSA advisories), which come from github.com/dsnet/compress v0.0.1's go.mod. They are not in the build: `govulncheck -scan module` and `./...` report nothing. Moving off dsnet/compress, or to a release of it that drops them, would also take them out of the graph. That should happen together with letsencrypt, whose pins these follow.
- **Drop `eventbus` from tacplus.yaml's `depends`** (2026-10-30, #6): it was there because "topics declared here publish through the eventbus broker". Since #6 blobstore publishes no topic, so nothing in the service uses the broker. In 2.5 a record is still an event, and its topic is still synthesized, so check that generation passes without the dependency before removing it. If it does not, the dependency should stay until tacplus removes the bus path for records (a major change, per tacplus docs/RECORD_EVENT_MODEL.md).
- **Watch nothing yet, by design** (2026-10-30, #6): `recordStore.Watch{Blobs,Sessions,Links,LinkStats}` are tested but have no consumer. Every path reads the row it acts on, at the time it acts. A pod-local cache of BlobLink rows, fed by `WatchLinks`, would take a Stratum round trip off every `/b/` resolve, but revocation must stay immediate (R7). It is only worth doing if the resolve latency turns out to matter.
- **ROADMAP.md: the "write records to Stratum directly" line is done** (2026-10-30, #6). Tenant routing of those calls is #8. Needs an agent at Jody's request.
- **ROADMAP.md: the tenant-owned blobstore line (#9) is done** (2026-11-01, #9), and #8 is closed as superseded by it. Needs an agent at Jody's request.
- **ROADMAP.md: the "Peers in Config, not env" line (#10) is done** (2026-11-05, scan): #10 was closed 2026-11-01 (`Config.peers` is the only source of the pair's wiring, `BLOBSTORE_PEERS` is not read; STATE.md), but ROADMAP.md still lists it under "Next". With #9 (above), "Next" would be empty. Needs an agent at Jody's request.
- **Consumers must take `upload_path` / `link_path` as given** (2026-10-30, #8): the paths are now `/upload/<tid>/<token>` and `/b/<tid>/<token>`. Any consumer (docmanager first) that builds a path from `token` instead of using the returned path breaks. Nothing consumes blobstore yet; say so in the consumer's integration when there is one.
- **Gateway: route the byte paths by their tid** (2026-11-01, #9): blobstore is tenant-owned, so `PUT /upload/<tid>/<token>` and `GET|HEAD /b/<tid>/<token>` must reach the instance of `<tid>`, by the same rule as an rpc's route field (the RPCs already carry `tenant` as their `route_field`, which the generated route table covers). The two HTTP prefixes are hand-proxied, not generated routes, so the gateway needs a rule for them: read the first path segment after the prefix, refuse anything that is not a tid (404), and dial that tenant's blobstore. Needs an issue on tacplus-dev/gateway, at Jody's request.
- **Operator: render one blobstore per tenant namespace** (2026-11-01, #9): the two-pod StatefulSet, its PVCs and `Config.peers` (`blobstore-0.blobstore.<tenant ns>:8081,...`) in the instance's typed Config, not `BLOBSTORE_PEERS`, which blobstore no longer reads (#10, operator#17), in each tenant namespace, with PVCs sized from the volume groups' declared bounds (`tenant_quota_bytes` summed over the groups, plus headroom for temp files). The registry now says `tenant_owned`; operator#3 deploys tenant-owned services per tenant. Check there that blobstore is covered.
- **Two services of one tenant uploading the same bytes into one group share one Blob row** (2026-11-01, #9): the key is `<group>/<sha256>` in the tenant's store and `PutBlob` overwrites, so the second upload takes over `owner_principal` (and the first owner's links then fail the owner check). This was already so for two services in one namespace before #9. A group is declared by one consuming service, so it should not happen; refusing a promote whose live row has another owner (409) would make it impossible. It is a content-existence answer only within the tenant.
- **A trace for the byte paths** (2026-11-03, #11): the RPC handlers now carry their request's `trace_id` to every record-plane call, but `GET|HEAD /b/<tid>/<token>` and `PUT /upload/<tid>/<token>` are hand-written HTTP handlers whose inbound request has no `trace_id` field, so their record calls (`FetchLink`, `FetchBlob`, `FetchSession`, `PutBlob`, the session settle) go out with none, and so do their peer forwards. They would carry it if the gateway passed one in a header (a `traceparent`, say) and `BytesHandler` put it in the context with `withTrace`. That needs a header the platform names (tacplus docs/USER.md, Distributed Tracing, names only field 200) and the gateway forwarding it. Once the byte paths have one, `ForwardUpload`'s `PUT /peer/upload/…` should carry it in `X-Trace-Id` (`PeerHeaderTrace`), the header `DeleteOnPeer` already sends (#12), and `servePeerUpload` should read it. If the platform names a different header, the peer one should be renamed to match.
- **looper-trace does not see blobstore's handlers** (2026-11-03, #11): `looper-trace check` reports `0 handlers` here, because the handlers take `(ctx, *servicemanager.Caller, *Request)` and reach the record plane through helpers (`h.svc.records`, `quota`, `settleSession`). `TestHandlersCarryTheirTraceToEveryRecordCall` is what covers them now. Reading the generated `BlobStoreHandler` interface for handler signatures would let the check find them. That change belongs in tacplus-dev/looper.
