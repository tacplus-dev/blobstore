# Proposals: blobstore

Written by loopers. Each proposal: what, why, links. Jody promotes accepted ones into ROADMAP.md (via an agent);
the looper then marks it `promoted` or `declined` here with the date.

## Open
- **ROADMAP.md: the floor is 2.5, not 2.4** (2026-10-29, #7): tacplus.yaml now declares `tacplus: "2.5"` (stratum, a dependency, needs 2.5). The "Now" line still says "tacplus floor 2.4 ... #1 still open", and the "Later" line "Declare the tacplus floor 2.4 (#1)" is replaced by #7; #3, #4, #5 and #2 are listed as blocked by #1, which #7 supersedes. Needs an agent at Jody's request.
- **ROADMAP.md: #3 is done; #5 may already be** (2026-10-29, #3): the module is `github.com/tacplus-dev/blobstore` and no SeaBeam reference is left outside PROVENANCE.md and the planning records (the gates now check it). ROADMAP.md's "Later" line for #3 can go. #5 is done too (Dockerfile base `alpine:3.24` as a build argument, gates and image build verified 2026-10-29), so a ROADMAP.md line for it can go as well. Needs an agent at Jody's request.
- **Old xz and klauspost/compress in the module graph** (2026-10-29, #4): `go list -m all` still lists github.com/ulikunitz/xz v0.5.6 and github.com/klauspost/compress v1.4.1 (GHSA advisories), which come from github.com/dsnet/compress v0.0.1's go.mod. They are not in the build: `govulncheck -scan module` and `./...` report nothing. Moving off dsnet/compress, or to a release of it that drops them, would also take them out of the graph. That should happen together with letsencrypt, whose pins these follow.
- **Drop `eventbus` from tacplus.yaml's `depends`** (2026-10-30, #6): it was there because "topics declared here publish through the eventbus broker". Since #6 blobstore publishes no topic, so nothing in the service uses the broker. In 2.5 a record is still an event, and its topic is still synthesized, so check that generation passes without the dependency before removing it. If it does not, the dependency should stay until tacplus removes the bus path for records (a major change, per tacplus docs/RECORD_EVENT_MODEL.md).
- **Watch nothing yet, by design** (2026-10-30, #6): `recordStore.Watch{Blobs,Sessions,Links,LinkStats}` are tested but have no consumer. Every path reads the row it acts on, at the time it acts. A pod-local cache of BlobLink rows, fed by `WatchLinks`, would take a Stratum round trip off every `/b/` resolve, but revocation must stay immediate (R7). It is only worth doing if the resolve latency turns out to matter.
- **ROADMAP.md: the "write records to Stratum directly" line is done** (2026-10-30, #6). Tenant routing of those calls is #8. Needs an agent at Jody's request.
- **README.md describes the upload token as an HMAC envelope** (2026-10-30, #8): it is a raw bearer token whose sha256 keys the UploadSession row (`internal/blobstore/token.go`), and the layout table says the same of `token.go`. Fix the two lines when README is next touched.
- **Consumers must take `upload_path` / `link_path` as given** (2026-10-30, #8): the paths are now `/upload/<tid>/<token>` and `/b/<tid>/<token>`. Any consumer (docmanager first) that builds a path from `token` instead of using the returned path breaks. Nothing consumes blobstore yet; say so in the consumer's integration when there is one.
